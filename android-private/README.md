# VALUE HUNTER AI Android試用版

本人が自分のAndroid 8以降の端末で使う非公開の試用版。株価取得・判定・通知は端末で行う。現在の日本株の接続試験では本人のJ-Quants APIキーを使う。

1. APKをインストールしてアプリを開く。
2. [J-Quants](https://jpx-jquants.com/ja)で各自のAPIキーを発行し、アプリの入力欄に貼り付ける。
3. 無料プランのチェックを付けた状態で「接続を保存して監視を開始」を押す。有料プランをすでに契約している場合はチェックを外せる。
4. Androidに通知を許可する。「無音通知を試す」を押すと通知欄で動作を確認できる。

初回の取得は比較の基準として保存される。次の取引日以降に条件を満たした銘柄が増えたときに通知される。Androidのバックグラウンド実行によって取得の時刻が前後する。「今すぐ確認」で手動確認できる。無料プランの株価は約12週間遅れで、アプリに基準日が表示される。

## 東証日報の終値を試す

Android 15以降で「東証日報で終値を確認」を押すと、JPXの公表済み株式相場表を取得し、極洋（1301）、王子ホールディングス（3861）、トヨタ自動車（7203）の終値・立会日・出典PDFを表示する。直近の公表日報2日分が取れた場合は、比較日と調整前終値の差額・変化率も表示する。以前の日報を取得できなかった場合も、直近の日報の結果は表示する。後場の終値を優先し、後場に終値がないときは前場の終値を表示する。日報の掲載は立会日の翌営業日。日報の立会日が取得先の日付と異なる場合は読み取りを中止する。

各社の公式決算をもとに、2026年3月期の実績EPS・BPSによる参考PER・PBRと、立会日より前に提出済みの自己株式控除後株数を、基準日・原本リンク付きで表示する。極洋と王子HDは2026年9月30日の中間決算、トヨタはEDINETの自己株券買付状況報告書（2026年9月30日・10月31日）を使用する。トヨタのEDINET記載の自己株式にはESOP信託の保有分が含まれない。参考PER・PBRは決算公表時の1株値で計算するため、決算後の株式分割・併合等は未反映。立会日当日の株数を使う時価総額は保留する。公表日しか確認できない開示は、同日の立会日には使わない。

終値から100株・1株の購入額（手数料を除く）を計算し、100株が10万円以内の銘柄を先に表示する。通期決算を使用した参考PER 15倍以下・参考PBR 1倍以下の照合結果も別に表示する。2日分の参考判定では、条件入り・条件外れ・100株枠と1株枠の移動を表示する。比較に必要な終値・通期決算がなければ保留する。JPX原本で財務基準日以降の権利落日が確認された銘柄は、参考PER・PBRと判定変化を保留する。期間内の月報を確認できない場合も判定変化を保留し、不足月を表示する。比較2日間をまたぐ権利落日が分かっている場合は、値動きの比較も保留する。

同梱の照合資料は2026年11月17日に確認した原本に基づく。月報は3～9月分、日次Excelは11月11～17日の公開分を照合した。日次Excelは見つかった権利落の確認に使い、未掲載を根拠に月報の不足を埋めない。同梱データは `android-private` で次を実行すると、公式目次から原本を取得して再生成できる。照合だけを試す場合は `--dry-run` を付ける。日次Excelの公開一覧から消えた確認済みの権利落日は保持する。取得や監査に失敗して処理を中断した場合は、既存ファイルをそのまま使う。

```sh
python3 -m pip install 'PyMuPDF>=1.24,<2' 'openpyxl>=3.1,<4' 'xlrd>=2,<3'
python3 tools/jpx_android_rights_refresh.py app/src/main/assets/jpx-share-rights.json --start-month 2026-03
```

GitHub Actionsの「Android JPX rights refresh」は平日の日本時間14:37にJPX原本を再照合し、差分があるときに限って照合データを `main` に反映する。Actions画面から手動実行もできる。更新したJSONがリポジトリの `main` に反映されると、アプリの「東証日報で終値を確認」で取得できる。画面に資料の日付と取得元を表示する。取得に失敗したり版が古かったりする場合は、端末で最後に照合できた版か、APK同梱版のうち新しい有効な資料を使う。資料の時点で未確認の月は保留する。

このボタンは手動の接続試験。取得したPDFは一時ファイルとして扱い、試験結果は監視履歴や候補一覧に登録しない。J-Quantsの監視設定は独立して使える。

「東証日報を定期確認し、参考条件入りを無音通知」をオンにすると、アプリを閉じた後も通信可能なときに約6時間ごとに確認する。Androidの電池節約等で実行が遅れる場合がある。監視をオンにした状態で「監視を今すぐ確認」を押すと、同じ処理を通信可能なときに1回追加で実行する。定期確認と監視履歴・重複防止を共有する。初回は基準日を保存し、以後は2日分の終値・通期決算・権利落ち資料を照合でき、新たに参考条件に入った銘柄を通知する。同じ取引日・銘柄の再通知は抑え、資料不足で保留の銘柄は通知しない。通知は既存の無音チャンネルを使う。監視欄では日本時間の最終確認、取得結果、立会日・比較日、銘柄ごとの保留理由を確認できる。版に変更がなかったり取得に失敗したりしたときも、最後に照合できた結果を表示する。

定期確認では、前回処理した日報2日分の版と権利落ち資料の版がそろって一致すればPDFの再取得を省く。日報が訂正された、資料の版が変わった、または配信元で版を確認できない場合はPDFを再取得する。端末には処理済みの版を識別するハッシュを保持し、日報PDFは一時ファイルとして扱う。

実機では「無音通知の設定を開く」から通知の有効・無効を確認し、「無音通知を試す」で監視と同じ通知チャンネルを確認できる。ロック画面への表示と画面の点灯は、端末の通知・ロック画面設定に従う。

## シンガポール株の接続試験

「シンガポール株 · S63接続試験」に本人の [DataCedar APIキー](https://datacedar.com/docs) を入れる。「S63の設定を保存して確認」を押すと、ST Engineeringの未調整終値とシンガポールの取引日が表示される。キーの認証や利用枠が原因で取得できないときは画面に状況を表示する。試験では最新の終値を参考為替で円換算し、1株と100株の金額を表示する。終値と同じ買付日付の株数が開示され、台帳に登録済みの場合に参考時価総額・PER・PBR、株数の開示日時、SGX原本URLも表示する。

S63の定期確認はチェックを入れて設定を保存した端末で有効になる。終値、同じ買付日付の開示株数、為替がそろった取引日を比較し、前の取引日では条件外だったS63が条件に入った場合に参考通知を出す。監視の初回判定を終えた後は、新しい取引日が条件に入ったときに、直前日もその時点の台帳と為替で照合し直す。直前日の材料が足りなければ、保留の理由と対象日を画面に表示し、同じ取引日の組み合わせを次回も確認する。最新日の終値が更新されたら、新しい直近2取引日を判定する。取引日付の株数は、確認済みのSGXNet開示をまとめたオンライン台帳から読み込む。一時的に取得できない場合は、端末で最後に確認した台帳を使う。端末に保存された台帳がなければ、アプリの同梱台帳を使う。翌日以降の開示も、公開後に買付日の終値と照合する。新しい開示を登録すれば、アプリを再インストールせずに反映できる。

## 米国株の一括取得の検証

[Massive Stocks Basic](https://massive.com/docs/rest/stocks/aggregates/daily-market-summary) は無料枠で米国株の日次終値を取引日単位で一括取得できる。取得はニューヨーク時間で取引日の翌日0時以降。個人のアプリで本人が使う前提で検証する。認証は本人の無料キーを使用する。

`MASSIVE_API_KEY` を設定したローカル環境で、終了済みの米国取引日を指定する。

```sh
python3 tools/us_massive_probe.py 2026-11-13
```

株式分割未調整の終値を、同日付の米国普通株リストと照合する。取得した行数、普通株の母数、終値を照合できた数、終値のない数を集計する。ETFなども入り得る日次データの行数と、普通株の件数は別に扱う。価格・銘柄別データ・キーは出力しない。認証済みの実データでの網羅率は未検証。アプリ本体の米国株接続としては上記のIBM接続試験が引き続き使える。

### 無料・APIキーなしの公開ファイル検証

`python3 tools/us_public_files_probe.py` は、Nasdaq Traderの公式ディレクトリ
[nasdaqlisted.txt](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt) と
[otherlisted.txt](https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt)
を `curl` で取得し、作成時刻を確認してETF・テスト銘柄などを除いた件数を集計する。

対象日を追加すると、登録不要の [MarketParquetの評価用ファイル](https://marketparquet.com/guides/free-historical-stock-data)
1件と完全一致のティッカーで照合する。`pyarrow` が必要。価格や銘柄一覧を出力せず、件数と照合率だけを表示する。

```sh
python3 tools/us_public_files_probe.py 2026-11-16
```

2026-11-13と11-16の日次サンプルを、11-17 06:00作成の銘柄一覧と照合した。
名称に普通株または普通持分の表記があり、他種類の表記のない5,341銘柄のうち、
11-13は5,181銘柄（97.00%）、11-16は5,217銘柄（97.68%）で価格が一致した。名称未分類と価格なしは別に集計する。
銘柄一覧は現在の掲載内容のため、日次サンプルと同日基準の網羅率ではない。

無料サンプルは評価用途で、価格は株式分割調整済み。端末で継続取得する運用、未調整終値、
同じ基準の株数との照合、正式なPER・PBR・通知への接続は引き続き検証が必要。

`--with-sec` を付けると、同じ検証で
[SECの公開企業・銘柄対応表](https://www.sec.gov/files/company_tickers_exchange.json)
も取得する。株価が取れた普通株候補のうち、11月13日は5,173銘柄、16日は5,208銘柄を
取引所情報と一意のSEC企業ID（CIK）に照合できた。
株式クラス別の銘柄が同じCIKを使う場合も検出する。CIKの一致は、株数や決算、
評価指標の検証済みを意味しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --with-sec
```

`--sec-quarter` を付けると、[SEC Financial Statement Data Sets](https://www.sec.gov/data-research/sec-markets-data/financial-statement-data-sets)
の公開ZIPもダウンロードする。取引日の前日までに提出された10-K・10-Q原本のうち、対象企業の直近の報告期間を選ぶ。
その報告書にある米ドル建ての株主資本と期間純利益を照合し、同じ値の重複は除き、異なる値が競合する場合は件数に含めない。
セグメント・共同登録者別の内訳も除く。複数のZIPを指定しても同じ銘柄は重複計上しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --sec-quarter 2026q3 --sec-quarter 2026q2
```

11月16日に終値サンプルとCIKが揃った5,208銘柄のうち、2026年Q3のZIPでは
3,699銘柄（3,677社）、Q2とQ3の両方では3,732銘柄（3,709社）で株主資本と期間純利益が揃った。
この件数は指定した提出時期のアーカイブの範囲に限る。純利益は10-Qの1四半期分または10-Kの通期分。
取引日の発行済株式数、直近12か月利益、未調整の終値は別途照合が必要。

直近12か月純利益も集計する。最新が10-Kならその通期純利益を使い、10-Qなら前年度通期純利益に
当年度累計純利益を足して前年同期累計純利益を引く。四半期番号、会計年度、期末月、米ドル建てが
一致し、必要な数値がそれぞれ一意のときだけ採用する。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

この4つのSEC原本で、終値サンプルとCIKのある5,208銘柄中、直近12か月純利益と株主資本が
揃ったのは3,376銘柄（3,355社）。取引日の発行済株式数はこの集計に含まない。

### NYSE・Nasdaqとダウ平均の内訳

NYSE本市場とNasdaqについて、普通株と読める上場数、終値、SEC企業ID、決算の照合件数を個別に確認できる。
NYSE Americanなどの別市場は従来どおり取引所別に集計する。

`--dow` は [State Street DIAの日次保有明細](https://www.ssga.com/us/en/individual/etfs/state-street-spdr-dow-jones-industrial-average-etf-trust-dia)
を取得し、現金を除いた30銘柄をダウ平均の確認に使う。日付の一致を確認してから終値を照合する。
DIAの読取りには `openpyxl` が必要。ダウ平均の指数値とETF価格は計算しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

2026-11-16の終値サンプルを11-17作成の取引所銘柄一覧に照合した結果。

| 対象 | 銘柄数 | 終値 | 終値とSEC企業ID | 直近12か月純利益と株主資本まで |
| --- | ---: | ---: | ---: | ---: |
| NYSE本市場の普通株候補 | 1,896 | 1,871 | 1,869 | 1,143 |
| Nasdaqの普通株候補 | 3,190 | 3,098 | 3,092 | 2,093 |
| DIAの11-16保有株 | 30 | 30 | 30 | 25 |

DIAの30銘柄の上場先はNYSEが21、Nasdaqが9。取引所の普通株候補は銘柄名による分類だが、
DIAの内訳では保有明細で確認した株を対象に含める。価格は分割調整済みの評価用サンプルで、
取引日時点の発行済株式数や正式なPER・PBRの検証は別途必要。

### SEC表紙の発行済み普通株式数

`--sec-notes` は [SEC Financial Statement and Notes Data Sets](https://www.sec.gov/data-research/sec-markets-data/financial-statement-notes-data-sets)
の月次公開ZIPを取得し、10-K・10-Q表紙の発行済み普通株式数を読む。
SECの月末丸めと日数差から原資料の株数基準日を復元する。取引日前日までの提出を対象とし、
数値の丸めや競合がある場合、株式クラスや銘柄の割当が確認できない場合は保留する。
`--sec-quarter` も指定すれば、同じ銘柄で直近12か月純利益・株主資本・日付付きの株数が揃った件数も出る。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-notes 2026-10 --sec-notes 2026-09 --sec-notes 2026-08 --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

この株数は開示で確認した基準日の値。以後の発行・買戻し・分割などを反映した取引日当日の値は別途照合が必要。

11月16日の終値サンプルとSEC企業IDが揃った5,208銘柄のうち、上記の3か月分の月次ZIPで
3,015銘柄に日付付き株数があり、うち441銘柄は11月16日まで30日以内の開示基準日だった。
四半期ZIPの決算も含めて揃ったのは2,583銘柄。NYSE本市場は789銘柄、Nasdaqは1,679銘柄、
DIA保有株は18銘柄だった。DIAは取引所と重複する。

### 株数の基準日以降に提出された書類

`--sec-index-quarter` は [SECのEDGAR四半期索引](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)
を取得する。株数の基準日から対象取引日までについて、株数を開示した元の書類を除き、
同じ企業の8-K・10-Qや証券登録届出書・目論見書などを確認対象として集計する。
基準日から対象取引日までの索引が欠ける場合は、書類なしと判定しない。
この集計は書類の候補を探すもので、株数変更の有無は書類本文と他の開示を確認する必要がある。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-notes 2026-10 --sec-notes 2026-09 --sec-notes 2026-08 --sec-index-quarter 2026q3 --sec-index-quarter 2026q4
```

11月16日分では、株数を確認した3,015銘柄のうち、追跡対象の書類があったのは2,959銘柄。
56銘柄は対象の書類種類が索引から見つからなかった。

### 月次ZIP未収録の決算書を原本から確認する

`us_sec_original_cover.py` は指定したNYSE・Nasdaq銘柄について、EDGAR四半期索引から取引日の
前日までに提出された最新の原本10-Kまたは10-Qを探し、添付のSEC抽出XBRLを確認する。
月次ZIPに含まれない翌月の提出分も、索引に掲載されていれば対象になる。

```sh
python3 tools/us_sec_original_cover.py 2026-11-16 --sec-index-quarter 2026q3 --sec-index-quarter 2026q4 --ticker AAPL --ticker MSFT --ticker IBM
```

原本の株数・基準日・提出日・開示精度・出典・対象範囲（企業または株式クラス）を出す。
複数株式クラスの企業は、表紙の取引シンボルと株数が同じ株式クラスを指す場合に取得する。
共同提出の別法人分は除外し、クラスや企業範囲が特定できない場合は保留する。対象は1回30銘柄まで。

Berkshire Hathawayは2026-10-28時点のA株480,476株とB株1,403,805,594株、
Southern Companyは2026-09-30時点の親会社1,164,261,029株を原本で確認した。
株式クラス単独の株数を企業全体の時価総額には使用しない。
開示された基準日以降の発行、買戻し、分割と、取引日の未調整終値は別途照合が必要。

### 公開Doltデータベースの日次終値を検証する

公開の [post-no-preference/stocks](https://www.dolthub.com/repositories/post-no-preference/stocks)
をDoltで同期したローカルDBから、指定取引日の終値を読める。アプリ用のAPI登録やCSV手入力は不要。
料金や銘柄数の条件を判断するための検証機能で、取得した価格は正式な割安判定に渡さない。

```sh
dolt clone --depth 1 post-no-preference/stocks stocks
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks
```

公開DBの照会では11月16日分が12,639行。Nasdaq Traderの同じ観測日の普通株候補と比較すると、
正の終値があったのはNYSE本市場で1,875 / 1,896（98.89%）、Nasdaqで3,102 / 3,190（97.24%）。
AppleとNVIDIAの過去の分割前後の終値には分割調整前の価格水準が残っていた。
この2例の確認で全銘柄の価格基準や正規取引時間の終値との一致を保証するものではない。

`--dolt-dir` に `--compare-marketparquet` を追加すると、同じ取引日に限り、取引所ごとに
Doltのみ、MarketParquetのみ、両方で1セント以内、両方で1セント超、どちらにもない件数を出す。
手元の原本を照合する場合は `--comparison-sample-file` も使える。
差の原因には株式分割の調整法や終値の採用基準があり得る。比較結果から価格を補完したり、
判定用の終値を自動で選んだりはしない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks --compare-marketparquet
```

過去の取引日を `--history-date` で最大5日指定すると、対象日に両ソースで終値がない銘柄を、
Doltで最後に確認できた日ごとに集計する。指定した過去日すべてで終値が得られなかった件数も表示する。
過去の価格を対象日の終値に流用しない。休場日や同期前の日は検査できない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks --compare-marketparquet \
  --history-date 2026-11-13 --history-date 2026-11-12
```

`--with-halts` を追加すると、終値が両方で欠けている銘柄を
[Nasdaq Traderの公開売買停止RSS](https://www.nasdaqtrader.com/Trader.aspx?id=TradeHaltRSS)と照合する。
`--halt-feed-file` で保存済みの公式RSSを再検証できる。配信時刻が対象日の翌日以降のものを使い、
停止開始日と再開日の間にある日だけを集計する。再開日が未記載の場合は配信時点の記録を使う。
一致する通知がない場合は停止の有無が未確認。終値の件数や価格を変更しない。

`--listing-evidence-file tools/evidence/us-listing-events-2026-11-16.json` を終値の比較に追加すると、
欠落銘柄について確認した上場・銘柄コード変更の出典と日付を表示する。発行体の開始予定と
取引所が通知した変更の効力発生日は別の種類として記録する。対象日より後の変更で旧コードが
指定されている場合は、二つの価格データに旧コードの当日値があるかを確認する。
旧コードの値を新コードに割り当てたり、取得率を変更したりしない。出典ファイルは調査用で、
掲載されている事例を再現できる。取引所の全履歴を取得する機能ではない。

### 取引日ごとの上場一覧を保存する

Nasdaq Traderが日中に更新する公開一覧2本を、米東部時間の日付で保存する。取引時間中など
毎日同じ時間帯に保存すると、日をまたいだ銘柄の変更を追いやすい。同じ日の再実行では、
最初に検証して保存したペアを使う。2本の作成日が異なる場合や、当日の作成分でない場合は保存しない。

```sh
python3 tools/us_public_files_probe.py --save-directory-to /path/to/us-listing-archive
python3 tools/us_public_files_probe.py 2026-11-17 \
  --directory-archive /path/to/us-listing-archive --dolt-dir stocks
```

日付指定での再生は、指定日に保存したペアが必要。別日のファイルや現在の一覧に切り替えない。
取引日と一致しても取引開始時点や引け時点の全銘柄を保証するものではない。

### 上場一覧の保存と終値照合を定時に実行する

Macなどのローカル環境で、Doltと同じ実行環境から次を使う。Python環境に
`exchange-calendars>=4.7,<5` を導入し、Doltの保存先の親ディレクトリを用意する。

```sh
python3 tools/us_daily_coverage.py --archive /path/to/us-listing-archive --dolt-dir /path/to/stocks
```

米東部時間の取引日12:00〜12:59に当日の一覧を保存する。先に保存した一覧は再利用する。
過去7暦日の保存済み取引日のうち、集計がまだない日についてDoltを同期し、同じ日の終値と照合する。
集計は一覧と同じ日付フォルダの `dolt-coverage.json` に保存する。対象日に有効な終値がない場合は
次の実行に持ち越す。それぞれの実行状況は標準出力に出る。取引日の判定にはXNYSカレンダーを使う。

日本時間のMacでcronを使う場合は火〜土曜の01:45と02:45に起動する。米東部時間の範囲内に
入るほうだけ処理するので、夏時間のたびに設定を変更する必要はない。
実行ファイルや保存先は絶対パスに置き換え、cronからもDoltが見えるようPATHを設定する。

```cron
45 1,2 * * 2-6 /path/to/python3 /path/to/tools/us_daily_coverage.py --archive /path/to/us-listing-archive --dolt-dir /path/to/stocks >> /path/to/us-coverage.log 2>&1
```
