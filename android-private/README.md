# 他力本願寺 VALUE HUNTER AI Android試用版

本人が自分の端末で使う非公開の株式モニター。現在のホーム画面は東証日報を使った日本株の確認と無音通知に対応する。APIキーの入力は不要。

1. 初回に通信量の案内を確認し、相場データの通信と東証の自動監視をオンにする。Android 15以降は標準のPDF読み取り、Android 14以下は互換モードを使う。
2. 「通知を有効にする」からAndroidの通知を許可する。
3. 「最新の確認」で取引日、比較日、保留理由を確認できる。「今すぐ更新」で監視と同じ処理を予約する。「終値と判定の詳細」で公表済みの日報を取得し、出典付きで確認できる。
4. 「自動監視」をオフにすると監視は停止する。次に開いたときも停止状態を保持する。

国内普通株の終値は東証日報から一括取得する。財務を登録している銘柄は極洋、積水ハウス、王子ホールディングス、三菱製紙、ENEOS、トヨタ自動車、キヤノン、丸紅、オリックス、NTT、KDDI、ソフトバンク。米国株（NYSE・Nasdaq）はAndroidが公開データから日次終値とSEC財務を取得する。シンガポール株（SGX）はホーム画面に準備中と表示する。

## 端末だけで診断ログを確認する

「通知」→「診断ログ」→「診断ログをコピー」で、実機で起きた通信・更新・通知・画面点灯の経過をコピーできる。端末内に直近240件を残し、相場の通信をオフにしていても開ける。時刻は日本時間。「予約を依頼」はAndroidに仕事を依頼した段階で、「実行開始」は実際に処理を始めた時刻。「Androidに点灯を要求」と「点灯を観測」は別の記録。コピーされるのは端末の機種・Androidの版・アプリのビルド番号と処理の状態や件数で、株価・認証情報・通知本文は含まれない。

USBを使える場合はAndroid StudioのLogcatでアプリのパッケージ `jp.valuehunter.privatewatch` を選び、`ValueHunterDiag` のタグでも同じイベントを追える。アプリが落ちた場合のスタックトレースはAndroidのLogcatで確認する。

## 割安アラートの境界を試す

「通知」→「割安アラートの境界」で、割安・かなり割安・超割安の最低点をそれぞれ変更して保存できる。初期値は60・75・85点。3つの値は昇順で、同じ点には設定できない。100株枠と1株参考枠を分けて、端末に保存した東証・米国株の日次データから段階別候補件数を再計算する。直前の取引日との両日照合ができた銘柄は、新規入り・昇格も試算する。

「割安メーターで通知」をオンにすると、前取引日と照合できた銘柄の新規入り・昇格を保存した境界で無音通知する。初期状態はオフで、従来の財務通知を使う。株価だけの予算チェックなど、財務以外の通知は個別の条件で動く。未取得の補助項目は仮に50点相当とし、確認できた資料で段階の上限を設ける。米国株は同じSEC年次書類で比較できる通期EPSと営業CFを再利用し、東証は保存されている比較可能な通期EPSを使う。同業比較と財務余力はまだ取得していないため、「超割安」は必要な裏付けが揃うまで表示されない。

## 3市場の判定方針と5年履歴の検証

対象は東証・NYSE／Nasdaq・SGX。取引日の価格と割安判定に必要な財務がそろった銘柄から算出し、海外株は基準日の確認できる為替で購入額を円に換算する。100株が10万円以下の候補を優先し、単元未満株を取り扱う銘柄は1株枠でも判定する。価格や財務が不足する銘柄は保留理由を残す。5年履歴は参考情報として扱い、履歴が短い銘柄も同じ割安条件で判定する。通知は新たに条件へ入った銘柄を対象にする。端末監視では国内普通株の購入額を一括判定し、予算内の銘柄の通期決算を自動取得して財務判定を行う。

東証の5年分の月末近辺の終値を、JPXの公開月間相場表から取得する調査ツール。Python 3とPopplerの `pdftotext` を使う。発行体ごとに当月の最終終値の日付を保持する。分割月などに複数行あり、行ごとの取引期間が重ならない場合は最後の行の終値を採用する。取引期間が重なる場合は保留する。PDFをローカルに再利用するには `--cache-dir` を指定する。`--include-prices` を省略すると、出力は件数・取得状態・出典のみ。

```sh
python3 tools/jpx_monthly_close_history.py 2026-10 1301 3861 7203 9432 9434 --cache-dir /tmp/value-hunter-jpx-history
```

2026年11月18日の検証では、2021年11月から2026年10月までの公式PDF60か月分を取得し、極洋、王子HD、トヨタ、NTT、ソフトバンクの月次終値を各60件確認した。NTTの2023年6月とソフトバンクの2024年9月は分割前後の行があり、後半の行から月内最終終値を取得した。この取得ツールの終値は未調整。米国・SGXの5年履歴は開発中。


過去の終値を同じ株数基準にそろえるには、JPX権利落ち月報を照合する。以下の例は
2021年10月から2026年9月までの60か月を対象にする。通常の株式分割・併合では権利落ち日より
前の価格に比率を適用する。月報の不足、同日の比率の矛盾、無償割当て等がある場合は保留する。
配当を含む総合収益率の計算は対象外。価格を含む入出力とPDFは手元で保持する。

```sh
python3 tools/jpx_monthly_close_history.py 2026-09 1301 3861 7203 9432 9434 --cache-dir /tmp/value-hunter-jpx-history --include-prices > /tmp/jpx-monthly-closes.json
python3 tools/jpx_adjust_monthly_history.py /tmp/jpx-monthly-closes.json --rights-cache /tmp/value-hunter-jpx-rights
```

この範囲でJPX原本60か月分の終値・権利落ち資料を照合し、5銘柄とも月次終値60件を
同じ株数基準にそろえた。NTTの1対25（2023年6月29日）とソフトバンクの1対10（2024年9月27日）を反映した。
2026年10月分の権利落ち月報は確認時点で未掲載だったため、検証の終点は2026年9月末。

`tools/value_candidate_screen.py` は判定の試作。終値・円換算・取扱単位の確認後に、PER 15倍以下かつPBR 1倍以下を優先候補とする。PERのみ条件を満たす場合はPBRが未取得か1.5倍以下、PBRのみ条件を満たす場合はPERが未取得か20倍以下なら参考候補。取得できた指標がゼロ以下なら参考候補へ回さず保留する。株式分割を調整済みの履歴を別途用意できた銘柄は、5年レンジ内の位置を参考表示に使える。Androidの東証日報監視にも、この2段階の財務判定を組み込んだ。過去データを使った通知件数の検証は未実施。

## 東証日報と決算を一括照合する

日報PDF、上場銘柄一覧、原本照合済みの通期財務JSON、取引日までの権利落ち月報を
ローカルで組み合わせる。銘柄の手動入力は不要。月報が足りない銘柄や取引日までに
開示されていない財務は保留する。結果は市場・取引日・取得区分・判定区分の件数のみ。
1株枠を含めるのは取扱いを確認した銘柄に `--single-share-code` を指定した場合。

```sh
rights=()
for report in /tmp/jpx-rights/rights-*.pdf; do
  rights+=(--rights-pdf "$report")
done
python3 tools/jpx_batch_financial_screen.py /tmp/jpx-daily.pdf \
  --jpx-universe /tmp/data_j.xlsx \
  --annual-financials tools/fixtures/jpx-annual-reference.json "${rights[@]}"
```

この例の通期財務は取得・照合経路の検証用に登録された極洋1銘柄分。判定件数は
指定した銘柄一覧の母集団に依存する。最新一覧を過去の日報に使った場合は、当時の市場全体の
正確な網羅率として扱わない。Androidへの接続と財務原本の一括収集は別工程。

2026年11月18日に、Androidにすでに登録した5銘柄の通期決算を使って原本を再検証した。
母集団は2026年10月末の内国普通株3,686銘柄。1株枠は指定せず、100株10万円以内で判定した。

| 立会日 | 確認した終値 | 100株予算内 | 決算と株数基準の照合済み | 優先候補 | 参考候補 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2026-09-30 | 3,645 | 1,263 | 5 | 1 | 1 |
| 2026-11-16 | 3,676 | 1,347 | 0 | 0 | 0 |

11月16日分は10・11月の月報が未掲載だったため、当時の財務登録5銘柄の株数基準を保留した。
検証はローカルで実施し、株価原本と銘柄ごとの結果はGitHubに保存していない。

## 東証日報の終値を試す

同梱する[東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)
の2026年10月末基準から、プライム・スタンダード・グロースの内国普通株3,686銘柄を照合する。
「最新の確認」と詳細画面には立会日、終値取得数、100株または1株で10万円以内の件数、
財務照合済み件数を表示する。これらの価格条件は終値での試算で、1株枠の実際の取扱いは証券会社による。
11月16日分の原本では、終値3,676銘柄、100株枠1,347銘柄、1株枠2,329銘柄だった。
銘柄一覧の更新はJPX公開の `data_j.xlsx` をダウンロードして次のコマンドで行う。

```sh
python3 tools/jpx_android_stock_universe.py /path/to/data_j.xlsx app/src/main/assets/jpx-stock-universe.txt
```

Android 15以降で「終値と判定の詳細」を押すと、JPXの公表済み株式相場表を取得し、極洋（1301）、王子ホールディングス（3861）、トヨタ自動車（7203）、NTT（9432）、ソフトバンク（9434）の終値・立会日・出典PDFを表示する。直近の公表日報2日分が取れた場合は、比較日と調整前終値の差額・変化率も表示する。以前の日報を取得できなかった場合も、直近の日報の結果は表示する。後場の終値を優先し、後場に終値がないときは前場の終値を表示する。日報の掲載は立会日の翌営業日。日報の立会日が取得先の日付と異なる場合は読み取りを中止する。

各社の公式決算をもとに、各社の通期決算の実績EPS・BPSによる参考PER・PBRと、立会日より前に提出済みの自己株式控除後株数を、基準日・原本リンク付きで表示する。極洋と王子HDは2026年9月30日の中間決算、トヨタはEDINETの自己株券買付状況報告書（2026年9月30日・10月31日）を使用する。NTTとソフトバンクの自己株式控除後株数は当該通期決算の期末値を表示する。トヨタのEDINET記載の自己株式にはESOP信託の保有分が含まれない。参考PER・PBRは決算公表時の1株値で計算するため、決算後の株式分割・併合等は未反映。立会日当日の株数を使う時価総額は保留する。公表日しか確認できない開示は、同日の立会日には使わない。

終値から100株・1株の購入額（手数料を除く）を計算し、100株が10万円以内の銘柄を先に表示する。通期決算を使用した財務判定で優先候補・参考候補を表示する。2日分の判定では、条件入り・条件外れ・優先度の変化・100株枠と1株枠の移動を表示する。比較に必要な終値・通期決算がなければ保留する。JPX原本で財務基準日以降の権利落日が確認された銘柄は、参考PER・PBRと判定変化を保留する。期間内に未公表の月報がある場合、Androidが東証上場会社情報サービスの決算・決定事実等の開示一覧を直接確認する。直近の月報より後の期間は、該当銘柄の一覧を全件取得でき、確認期間に関係し得る分割・併合等の開示が検出されないときだけ補完する。開示の判別が必要なときや資料が不足するときは判定を保留する。比較2日間をまたぐ権利落日が分かっている場合は、値動きの比較も保留する。

同梱の照合資料は2026年11月19日に監視12銘柄を含めて原本を再監査した。月報は1～9月分の9ファイル、日次Excelは公開中の5ファイルを照合した。10・11月の月報は取得時点で目次に掲載されていなかった。日次Excelは見つかった権利落の確認に使い、未掲載を根拠に月報の不足を埋めない。同梱データは `android-private` で次を実行すると、公式目次から原本を取得して再生成できる。照合だけを試す場合は `--dry-run` を付ける。監視銘柄を拡張する際は `--include-code CODE` を追加し、公式原本の再監査を実行する。日次Excelの公開一覧から消えた確認済みの権利落日は保持する。取得や監査に失敗して処理を中断した場合は、既存ファイルをそのまま使う。

```sh
python3 -m pip install 'PyMuPDF>=1.24,<2' 'openpyxl>=3.1,<4' 'xlrd>=2,<3'
python3 tools/jpx_android_rights_refresh.py app/src/main/assets/jpx-share-rights.json --start-month 2026-01
```

GitHub Actionsの「Android JPX rights refresh」は平日の日本時間14:37にJPX原本を再照合し、差分があるときに限って照合データを `main` に反映する。Actions画面から手動実行もできる。更新したJSONがリポジトリの `main` に反映されると、アプリの「終値と判定の詳細」で取得できる。画面に資料の日付と取得元を表示する。取得に失敗したり版が古かったりする場合は、端末で最後に照合できた版か、APK同梱版のうち新しい有効な資料を使う。資料の時点で未確認の月は保留する。

このボタンは手動の接続試験。取得したPDFは一時ファイルとして扱い、試験結果は監視履歴や候補一覧に登録しない。

「自動監視」をオンにすると、アプリを閉じた後も通信可能なときに約6時間ごとに確認する。Androidの電池節約等で実行が遅れる場合がある。監視をオンにした状態で「今すぐ更新」を押すと、同じ処理を通信可能なときに1回追加で実行する。定期確認と監視履歴・重複防止を共有する。初回は基準日を保存し、以後は2日分の終値・通期決算・権利落ち資料を照合でき、新たに優先・参考候補に入った銘柄、または参考から優先に上がった銘柄を通知する。同じ取引日・銘柄の再通知は抑え、資料不足で保留の銘柄は通知しない。通知は既存の無音チャンネルを使う。監視欄では日本時間の最終確認、取得結果、立会日・比較日、銘柄ごとの保留理由を確認できる。版に変更がなかったり取得に失敗したりしたときも、最後に照合できた結果を表示する。

### 東証の通期財務の自動取得

東証の日報から購入額10万円以内の銘柄を選び、通常は1回最大24銘柄、初回確認が多く残る間は最大96銘柄の決算をAndroidで確認する。新しい開示の照合を優先し、初回取得では100株枠から1株枠の順に進める。定期的な再取得は初回取得の後に回す。東証上場会社情報サービスに公開された決算短信のサマリー（Inline XBRL）から、銘柄コード・開示日・通期の期間・日本円の単位を照合し、実績の基本的EPSとBPSを保存する。APIキー、手動登録、Macからの同期は不要。取得できた銘柄は次回以降も判定に使う。

自動監視中は通常の日報確認に加え、通常は約30分ごとに財務の取得・更新を再開する。初回確認が残り、正常に進捗を保存できた定期実行では、次回を完了から15分後に予約する。版が一致する日報は同じプロセス内で解析結果を再利用する。再起動後は端末内に保存した解析結果と公式の版・立会日・対象銘柄一覧を照合し、一致した日報のPDF再取得を省く。「今すぐ更新」でも財務を1回分進める。取得済みの銘柄は新しい開示を検知した際と21日経過時に再照合し、サマリー不足等は7日後に再試行する。個別銘柄の一時エラーは1時間後に再試行し、他銘柄の取得を進める。配信元の429・503応答では最後に確認した銘柄まで保存して取得を中断し、1時間または配信元が示した長い方の時間を置いて再開する。複数銘柄で通信障害が続く場合もその回の取得を中断する。実行間隔はAndroidのバックグラウンド制御に従う。

株式分割・併合などの該当開示、未確認の日次開示、照合できない訂正、期間や通貨の違いがある場合は保留する。取得件数、予算内の件数、訂正版のiXBRL欠落などの取得保留理由と件数を監視画面に表示する。新しい決算を取得したときは照合済みの直前の決算を残し、各立会日より前に公開された数値で比較する。割安条件への新規該当、参考候補から優先候補への移行、100株で10万円以下への初回移行を通知し、同じ立会日・銘柄の再通知を抑止する。詳細画面で自動取得した候補のPER・PBRと決算原本を確認できる。

## Androidに過去の終値レンジを表示する

前節の調整ツールの要約をローカルに出力し、本人用APKのビルド時に渡す。


最新の立会日より後の履歴や調整が保留された履歴は表示対象から外れる。
履歴末から直近の立会日までに株式分割等がなく、権利落ち月報がそろっているときは、
直近終値の位置またはレンジ超過を表示する。確認資料が足りない場合には比較を保留する。
上下限のない旧要約からも履歴末時点のレンジ位置を表示できる。
日次のPER・PBR判定と無音通知は従来の財務・権利落ち照合を使う。
更新した要約を同じプロパティで渡して再ビルドすると履歴が更新される。
本人用の要約とそれを含むAPKはGitHubに置かない。

SEC原本を全市場普通株候補5,084銘柄の一覧に適用し、11月16〜18日を再生した。終値とSEC銘柄照合を通った4,595・4,573・4,565銘柄を日別に処理。途中の保存状態を読み直した差分更新と、各日の原本を全件読み直した結果は3日とも一致した。照合済み財務は2,762・2,762・2,758銘柄。東証は実データ72銘柄を同じ3日間で再生した。TDnetの訂正行でページ全体が保留される問題を修正し、11月19日の公式216件を全3ページから取得。サンプルの同日の財務判定数は18→52銘柄。3,686銘柄規模の取得キューと通信制限後の完走も模擬入力で確認した。東証の全銘柄の財務原本取得を通した検証と、改修後のJPX定期ワークフローの実行確認は残っている。

`tools/JpxFinancialBatch.java` は公式日報から抽出して日付を照合済みのTSVを使い、Androidと同じ決算取得・判定を小分けに再生する。引数は取引日、銘柄コードと終値のTSV（終値がない行は第2列を空欄）、JPX権利落ちJSON、開始コード、実行件数。実データの検証時は既存のAndroid JVMクラスパスと `pdftotext` を使う。原本URLと受信バイト列のSHA-256、判定区分、保留理由を出力する。出力されたJSONを `scripts/audit_jpx_financial_evidence.py` で集計する。値付き原本は公開しない。NYSE・Nasdaqの予算入り通知は、価格の取得経路が切り替わった後も、同日・同一銘柄の送信済み履歴を使う。

最後の引数に `--serial` を付けると、1銘柄ずつ取得して12件ごとの累積時間を標準エラーに出す。これは開発環境の原本取得時間で、Androidの実行間隔やアプリ内保存に要する時間は別途計測する。

JPXが429または503を返したときは、バッチが残りの取得を見送り、`paused: true` を出力する。時間を置いて `source_unavailable` と `rate_limited_before_request` の銘柄を再照合できる。

### 無料・APIキーなしの公開ファイル検証

`python3 tools/us_public_files_probe.py` は、Nasdaq Traderの公式ディレクトリ
[nasdaqlisted.txt](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt) と
[otherlisted.txt](https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt)
を `curl` で取得し、作成時刻を確認してETF・テスト銘柄などを除いた件数を集計する。

対象日を追加すると、登録不要の [MarketParquetの評価用ファイル](https://marketparquet.com/guides/free-historical-stock-data)
1件と完全一致のティッカーで照合する。`pyarrow` が必要。価格や銘柄一覧を出力せず、件数と照合率だけを表示する。

```sh
python3 tools/us_public_files_probe.py 2026-11-16
```

2026-11-13と11-16の日次サンプルを、11-17 06:00作成の銘柄一覧と照合した。
名称に普通株または普通持分の表記があり、他種類の表記のない5,341銘柄のうち、
11-13は5,181銘柄（97.00%）、11-16は5,217銘柄（97.68%）で価格が一致した。名称未分類と価格なしは別に集計する。
銘柄一覧は現在の掲載内容のため、日次サンプルと同日基準の網羅率ではない。

無料サンプルは評価用途で、価格は株式分割調整済み。端末で継続取得する運用、未調整終値、
同じ基準の株数との照合、正式なPER・PBR・通知への接続は引き続き検証が必要。

`--with-sec` を付けると、同じ検証で
[SECの公開企業・銘柄対応表](https://www.sec.gov/files/company_tickers_exchange.json)
も取得する。株価が取れた普通株候補のうち、11月13日は5,173銘柄、16日は5,208銘柄を
取引所情報と一意のSEC企業ID（CIK）に照合できた。
株式クラス別の銘柄が同じCIKを使う場合も検出する。CIKの一致は、株数や決算、
評価指標の検証済みを意味しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --with-sec
```

`--sec-quarter` を付けると、[SEC Financial Statement Data Sets](https://www.sec.gov/data-research/sec-markets-data/financial-statement-data-sets)
の公開ZIPもダウンロードする。取引日の前日までに提出された10-K・10-Q原本のうち、対象企業の直近の報告期間を選ぶ。
その報告書にある米ドル建ての株主資本と期間純利益を照合し、同じ値の重複は除き、異なる値が競合する場合は件数に含めない。
セグメント・共同登録者別の内訳も除く。複数のZIPを指定しても同じ銘柄は重複計上しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --sec-quarter 2026q3 --sec-quarter 2026q2
```

11月16日に終値サンプルとCIKが揃った5,208銘柄のうち、2026年Q3のZIPでは
3,699銘柄（3,677社）、Q2とQ3の両方では3,732銘柄（3,709社）で株主資本と期間純利益が揃った。
この件数は指定した提出時期のアーカイブの範囲に限る。純利益は10-Qの1四半期分または10-Kの通期分。
取引日の発行済株式数、直近12か月利益、未調整の終値は別途照合が必要。

直近12か月純利益も集計する。最新が10-Kならその通期純利益を使い、10-Qなら前年度通期純利益に
当年度累計純利益を足して前年同期累計純利益を引く。四半期番号、会計年度、期末月、米ドル建てが
一致し、必要な数値がそれぞれ一意のときだけ採用する。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

この4つのSEC原本で、終値サンプルとCIKのある5,208銘柄中、直近12か月純利益と株主資本が
揃ったのは3,376銘柄（3,355社）。取引日の発行済株式数はこの集計に含まない。

### NYSE・Nasdaqとダウ平均の内訳

NYSE本市場とNasdaqについて、普通株と読める上場数、終値、SEC企業ID、決算の照合件数を個別に確認できる。
NYSE Americanなどの別市場は従来どおり取引所別に集計する。

`--dow` は [State Street DIAの日次保有明細](https://www.ssga.com/us/en/individual/etfs/state-street-spdr-dow-jones-industrial-average-etf-trust-dia)
を取得し、現金を除いた30銘柄をダウ平均の確認に使う。日付の一致を確認してから終値を照合する。
DIAの読取りには `openpyxl` が必要。ダウ平均の指数値とETF価格は計算しない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

2026-11-16の終値サンプルを11-17作成の取引所銘柄一覧に照合した結果。

| 対象 | 銘柄数 | 終値 | 終値とSEC企業ID | 直近12か月純利益と株主資本まで |
| --- | ---: | ---: | ---: | ---: |
| NYSE本市場の普通株候補 | 1,896 | 1,871 | 1,869 | 1,143 |
| Nasdaqの普通株候補 | 3,190 | 3,098 | 3,092 | 2,093 |
| DIAの11-16保有株 | 30 | 30 | 30 | 25 |

DIAの30銘柄の上場先はNYSEが21、Nasdaqが9。取引所の普通株候補は銘柄名による分類だが、
DIAの内訳では保有明細で確認した株を対象に含める。価格は分割調整済みの評価用サンプルで、
取引日時点の発行済株式数や正式なPER・PBRの検証は別途必要。

### SEC表紙の発行済み普通株式数

`--sec-notes` は [SEC Financial Statement and Notes Data Sets](https://www.sec.gov/data-research/sec-markets-data/financial-statement-notes-data-sets)
の月次公開ZIPを取得し、10-K・10-Q表紙の発行済み普通株式数を読む。
SECの月末丸めと日数差から原資料の株数基準日を復元する。取引日前日までの提出を対象とし、
数値の丸めや競合がある場合、株式クラスや銘柄の割当が確認できない場合は保留する。
`--sec-quarter` も指定すれば、同じ銘柄で直近12か月純利益・株主資本・日付付きの株数が揃った件数も出る。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-notes 2026-10 --sec-notes 2026-09 --sec-notes 2026-08 --sec-quarter 2026q3 --sec-quarter 2026q2 --sec-quarter 2026q1 --sec-quarter 2025q4
```

この株数は開示で確認した基準日の値。以後の発行・買戻し・分割などを反映した取引日当日の値は別途照合が必要。

11月16日の終値サンプルとSEC企業IDが揃った5,208銘柄のうち、上記の3か月分の月次ZIPで
3,015銘柄に日付付き株数があり、うち441銘柄は11月16日まで30日以内の開示基準日だった。
四半期ZIPの決算も含めて揃ったのは2,583銘柄。NYSE本市場は789銘柄、Nasdaqは1,679銘柄、
DIA保有株は18銘柄だった。DIAは取引所と重複する。

### 株数の基準日以降に提出された書類

`--sec-index-quarter` は [SECのEDGAR四半期索引](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)
を取得する。株数の基準日から対象取引日までについて、株数を開示した元の書類を除き、
同じ企業の8-K・10-Qや証券登録届出書・目論見書などを確認対象として集計する。
基準日から対象取引日までの索引が欠ける場合は、書類なしと判定しない。
この集計は書類の候補を探すもので、株数変更の有無は書類本文と他の開示を確認する必要がある。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dow --sec-notes 2026-10 --sec-notes 2026-09 --sec-notes 2026-08 --sec-index-quarter 2026q3 --sec-index-quarter 2026q4
```

11月16日分では、株数を確認した3,015銘柄のうち、追跡対象の書類があったのは2,959銘柄。
56銘柄は対象の書類種類が索引から見つからなかった。

### 月次ZIP未収録の決算書を原本から確認する

`us_sec_original_cover.py` は指定したNYSE・Nasdaq銘柄について、EDGAR四半期索引から取引日の
前日までに提出された最新の原本10-Kまたは10-Qを探し、添付のSEC抽出XBRLを確認する。
月次ZIPに含まれない翌月の提出分も、索引に掲載されていれば対象になる。

```sh
python3 tools/us_sec_original_cover.py 2026-11-16 --sec-index-quarter 2026q3 --sec-index-quarter 2026q4 --ticker AAPL --ticker MSFT --ticker IBM
```

原本の株数・基準日・提出日・開示精度・出典・対象範囲（企業または株式クラス）を出す。
複数株式クラスの企業は、表紙の取引シンボルと株数が同じ株式クラスを指す場合に取得する。
共同提出の別法人分は除外し、クラスや企業範囲が特定できない場合は保留する。対象は1回30銘柄まで。

Berkshire Hathawayは2026-10-28時点のA株480,476株とB株1,403,805,594株、
Southern Companyは2026-09-30時点の親会社1,164,261,029株を原本で確認した。
株式クラス単独の株数を企業全体の時価総額には使用しない。
開示された基準日以降の発行、買戻し、分割と、取引日の未調整終値は別途照合が必要。

### 公開Doltデータベースの日次終値を検証する

公開の [post-no-preference/stocks](https://www.dolthub.com/repositories/post-no-preference/stocks)
をDoltで同期したローカルDBから、指定取引日の終値を読める。アプリ用のAPI登録やCSV手入力は不要。
料金や銘柄数の条件を判断するための検証機能で、取得した価格は正式な割安判定に渡さない。

```sh
dolt clone --depth 1 post-no-preference/stocks stocks
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks
```

公開DBの照会では11月16日分が12,639行。Nasdaq Traderの同じ観測日の普通株候補と比較すると、
正の終値があったのはNYSE本市場で1,875 / 1,896（98.89%）、Nasdaqで3,102 / 3,190（97.24%）。
AppleとNVIDIAの過去の分割前後の終値には分割調整前の価格水準が残っていた。
この2例の確認で全銘柄の価格基準や正規取引時間の終値との一致を保証するものではない。

`--dolt-dir` に `--compare-marketparquet` を追加すると、同じ取引日に限り、取引所ごとに
Doltのみ、MarketParquetのみ、両方で1セント以内、両方で1セント超、どちらにもない件数を出す。
手元の原本を照合する場合は `--comparison-sample-file` も使える。
差の原因には株式分割の調整法や終値の採用基準があり得る。比較結果から価格を補完したり、
判定用の終値を自動で選んだりはしない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks --compare-marketparquet
```

過去の取引日を `--history-date` で最大5日指定すると、対象日に両ソースで終値がない銘柄を、
Doltで最後に確認できた日ごとに集計する。指定した過去日すべてで終値が得られなかった件数も表示する。
過去の価格を対象日の終値に流用しない。休場日や同期前の日は検査できない。

```sh
python3 tools/us_public_files_probe.py 2026-11-16 --dolt-dir stocks --compare-marketparquet \
  --history-date 2026-11-13 --history-date 2026-11-12
```

`--with-halts` を追加すると、終値が両方で欠けている銘柄を
[Nasdaq Traderの公開売買停止RSS](https://www.nasdaqtrader.com/Trader.aspx?id=TradeHaltRSS)と照合する。
`--halt-feed-file` で保存済みの公式RSSを再検証できる。配信時刻が対象日の翌日以降のものを使い、
停止開始日と再開日の間にある日だけを集計する。再開日が未記載の場合は配信時点の記録を使う。
一致する通知がない場合は停止の有無が未確認。終値の件数や価格を変更しない。

`--listing-evidence-file tools/evidence/us-listing-events-2026-11-16.json` を終値の比較に追加すると、
欠落銘柄について確認した上場・銘柄コード変更の出典と日付を表示する。発行体の開始予定と
取引所が通知した変更の効力発生日は別の種類として記録する。対象日より後の変更で旧コードが
指定されている場合は、二つの価格データに旧コードの当日値があるかを確認する。
旧コードの値を新コードに割り当てたり、取得率を変更したりしない。出典ファイルは調査用で、
掲載されている事例を再現できる。取引所の全履歴を取得する機能ではない。

### 取引日ごとの上場一覧を保存する

Nasdaq Traderが日中に更新する公開一覧2本を、米東部時間の日付で保存する。取引時間中など
毎日同じ時間帯に保存すると、日をまたいだ銘柄の変更を追いやすい。同じ日の再実行では、
最初に検証して保存したペアを使う。2本の作成日が異なる場合や、当日の作成分でない場合は保存しない。

```sh
python3 tools/us_public_files_probe.py --save-directory-to /path/to/us-listing-archive
python3 tools/us_public_files_probe.py 2026-11-17 \
  --directory-archive /path/to/us-listing-archive --dolt-dir stocks
```

日付指定での再生は、指定日に保存したペアが必要。別日のファイルや現在の一覧に切り替えない。
取引日と一致しても取引開始時点や引け時点の全銘柄を保証するものではない。

### 上場一覧の保存と終値照合を定時に実行する

Macなどのローカル環境で、Doltと同じ実行環境から次を使う。Python環境に
`exchange-calendars>=4.7,<5` を導入し、Doltの保存先の親ディレクトリを用意する。

```sh
python3 tools/us_daily_coverage.py --archive /path/to/us-listing-archive --dolt-dir /path/to/stocks
```

米東部時間の取引日12:00〜12:59に当日の一覧を保存する。先に保存した一覧は再利用する。
過去7暦日内に一覧を保存した取引日を、定時実行ごとにDoltの同日終値と照合する。
終値が後日追加・修正された場合は、すでに集計済みの日も更新する。集計は日付フォルダの
`dolt-coverage.json` に観測時刻付きで保存し、配布元の全件確定を示すものではない。
有効な終値を取得できない場合は前回の集計を保持する。標準出力に処理状況と市場別件数を出す。
前回の集計と照合条件が一致するときは、NYSE・Nasdaqごとの終値取得件数の増減も、集計と
標準出力の両方に `previous_observation` として記録する。上場一覧2本のSHA-256も記録し、
作成時刻が同じでも内容が違う一覧での増減を比較しない。旧形式はタイムスタンプと対象件数で照合する。
日付別レポートの `missing_close_symbols_by_exchange` に未取得のティッカーを保存する。
前回と今回の一覧のハッシュが一致する場合は、`previous_observation` に取得できるようになった銘柄と
新たに欠けた銘柄を記録する。総件数が同じでも銘柄の入れ替わりを確認できる。
取引日の判定にはXNYSカレンダーを使う。

日本時間のMacでcronを使う場合は火〜土曜の01:45と02:45に起動する。米東部時間の範囲内に
入るほうだけ処理するので、夏時間のたびに設定を変更する必要はない。
実行ファイルや保存先は絶対パスに置き換え、cronからもDoltが見えるようPATHを設定する。

```cron
45 1,2 * * 2-6 /path/to/python3 /path/to/tools/us_daily_coverage.py --archive /path/to/us-listing-archive --dolt-dir /path/to/stocks >> /path/to/us-coverage.log 2>&1
```

ダウ構成株の終値件数も確認する場合は、同じコマンドに `--with-dow` を付け、
Python環境に `openpyxl` を追加する。[State StreetのDIA日次保有明細](https://www.ssga.com/us/en/individual/etfs/state-street-spdr-dow-jones-industrial-average-etf-trust-dia)
から現金を除く30銘柄を検証し、明細記載の基準日で `dia-holdings/YYYY-MM-DD.xlsx` に
保存する。価格と明細の日付が一致する場合だけ `dia_holdings_comparison` を出す。
明細の取得・再生が失敗した場合も、NYSE・Nasdaqの終値照合は続ける。
DIA保有明細はダウ構成銘柄を確認するための近似資料。

別ソースも照合するときは、同じコマンドに `--compare-marketparquet` を付け、
Python環境に `pyarrow` を追加する。MarketParquetの登録不要の公開サンプルで対象日が取得できる場合、
MarketParquetだけで確認できた銘柄、両ソースで欠けた銘柄、価格差の件数を日付別レポートに記録する。
公開サンプルは期間が限られ、入手できない日や日付不一致は照合できなかった理由を残す。
MarketParquetは分割調整済みのため、Doltの終値や取得件数には合算しない。

### NYSE公開サンプルのLastとDoltを照合する

[NYSE TAQの公式公開サンプル](https://ftp.nyse.com/Historical%20Data%20Samples/TAQ%20CLOSING%20PRICES/)
のNYSEファイルを元の名前で保存する。照合ではNYSE上場コード `N`、英字のみのティッカー、
対象日と一致する行の日付、正のLastと出来高を確認する。`--with-share-classes` を付けると、
[NYSEの表記規則](https://www.nyse.com/publicdocs/nyse/data/NYSE_Symbology_Spec.pdf)に従い、
末尾が空白とAまたはBの行をドット付きのクラス銘柄として照合する。結果の
`share_class_scope` に対象件数と欠落・差異銘柄を出す。優先株・新株発行前取引等の接尾辞は対象外。
一致件数と価格差を集計し、NYSEのLastを正規セッションの公式終値と断定したり、
割安判定用の価格に採用したりはしない。公開サンプルの提供日以外の日次取得には使えない。

```sh
python3 tools/us_nyse_taq_probe.py 2026-07-01 --nyse-sample-file EQY_US_NYSE_SUM_CLOSE_20260701.txt --dolt-dir stocks
```

レポートの `exceptions` に、Doltに当日行がない銘柄、当日行はあるが有効な終値がない銘柄、
NYSEのLastとの差が1セントを超えた銘柄を記録する。原因調査にはこのティッカーを使い、
他クラスの値や別日の値は流用しない。

`--follow-through 2026-07-10` を追加すると、当日のDoltで有効な終値がなかった銘柄について、
指定日までで最も早い有効な終値の日付をローカルDBから確認する。結果は `dolt_follow_up` に記録する。
確認できるのは現在のDBに収録されている価格の日付。配布元がいつその行を追加したかを調べるには、
配布元の更新履歴も必要になる。追跡に失敗した場合も、対象日の照合結果は出力する。

### Nasdaqの公式終値メッセージが含まれるか検査する

[Nasdaq NLS 4.0の公開テストキャプチャ](https://emi.nasdaq.com/Basic_NLS/NLS%204.0/)を
ローカルに保存し、Ethernet/IPv4/UDPのPCAPからNasdaq上場銘柄への公式終値通知を探す。

```sh
python3 tools/us_nasdaq_nls_probe.py 'nls_4 1.pcap'
```

NLS 4.0の約定メッセージのうち、発信元と上場市場がNasdaqで、第4売買条件が `M` の行を数える。
キャプチャ内の同一銘柄の価格が複数ある場合は要確認として出力する。出力は銘柄と件数で、価格は出さない。
テストキャプチャでの通知有無を調べるための機能で、取消・訂正を反映した日次価格の生成や全市場カバー率の算定には別途完全な取引日データが必要。

[NLS Plusの2021年6月14日 Tape C公開サンプル](https://emi.nasdaq.com/Basic_NLS/NLS/)は
`--tape-c` でストリーム処理できる。元ファイル名の年月日とシステムの開始・終了イベントを確認し、
Nasdaq上場銘柄に対するNOCP通知と取引所横断の集計終値を個別に集計する。
同じ銘柄に複数の異なる価格がある場合は集計対象外として記録する。
同日Doltの照合は `--dolt-dir` を指定した場合に実行する。

```sh
python3 tools/us_nasdaq_nls_probe.py --tape-c 06142021_nlsplus_tape_c.gz --dolt-dir stocks
```

Tape C照合の `exceptions` には、Doltに当日の行がない銘柄、行はあるが有効な終値がない銘柄、
照合した価格に1セント超の差がある銘柄を出す。完全一致数は `exact_matches`、
完全一致を含む1セント以内の件数は `within_one_cent`。公開サンプルの上場銘柄にはETFなども含まれる。

`nocp_differences_vs_consolidated` は、DoltとNOCPに1セント超の差が出た同じ銘柄だけを対象に、
Doltと取引所横断の集計終値がどれだけ一致するかを出す。集計終値が欠けている場合や値が複数ある場合も、
銘柄別に記録する。これにより同じ対象群の中で終値の定義による差を調べられる。

## 米国株の終値の定期取得

初回起動で通信可能時の定期更新（6時間間隔のWorkManager）を登録する。既定のデータ元はDoltHubの公開データセット [post-no-preference/stocks](https://www.dolthub.com/repositories/post-no-preference/stocks)。無料でキー登録不要。米東部の前日以前を照会し、週末や結果0件の日は繰り戻す。同一リビジョンの終値を全ページ取得し、件数・取引日・重複を確認して最新1取引日分を端末内に保存する。画面には取得日と件数を表示する。DoltHubの終値は参考値として扱う。画面の件数は全取得行で、普通株だけの網羅件数は別途照合する。

Massive Stocks Basicは任意の代替経路。無料キーだけを書いたテキストファイルをビルドするPCのリポジトリ外に置き、Android StudioのGradle実行構成に `-PmassiveKeyFile=/絶対パス/massive-key.txt` を設定するか、`android-private` から `gradle -PmassiveKeyFile=/絶対パス/massive-key.txt :app:assembleDebug` を実行する。設定したビルドはMassiveの未調整終値を使う。APK内のキーは取り出せるため、本人の端末用のAPKとして扱う。実配信の検査は、PCのローカル環境変数 `MASSIVE_API_KEY` を設定して `python tools/us_massive_probe.py YYYY-MM-DD` を複数の完了済み取引日について実行する。

終値の財務・株数との照合には、端末の非公開キャッシュ `no_backup/us-daily-closes.json` を手元で取得し、`python tools/us_public_files_probe.py YYYY-MM-DD --dolt-android-file /ローカル/us-daily-closes.json --with-sec` を使う。Massiveのキャッシュは `--massive-android-file` を指定する。財務・株数の内訳を計測する場合は既存の `--sec-quarter` と `--sec-notes` も使える。

Android端末では IBM、AAPL、HPQ、AMD、INTC、GM の6銘柄について、SEC Company Factsの開示とUSD/JPYを自動取得し、最新の終値に対する試験的な時価総額・PER・PBR・円換算額を米国株欄に表示する。株数に発行時点との差があり得るため参考判定とする。決算期末と開示日、株数基準日を区別し、確認できる分割や赤字・負の自己資本は保留にする。

同じ6銘柄には過去60か月の月末近くの参考終値レンジも表示する。比較対象は完了済みの月で、各月の終盤3平日から最後に取得できた日を使う。更新は月単位。通信エラー後は取得済みの12か月区間を再利用する。履歴が60か月に満たない場合や分割記録がある場合はレンジを保留する。

### NYSE・Nasdaqの普通株候補を一括照合

米国株欄は定期更新時に Nasdaq Trader の公開銘柄一覧を読み、NYSE本市場・Nasdaqそれぞれの終値取得件数と不足数を表示する。一覧の作成日も表示する。市場の分類は銘柄名称の普通株表記に基づく。

SECの無料公開一括ファイル `companyfacts.zip` と端末の終値キャッシュを使うと、Androidと同じ財務抽出処理で一括照合できる。株式クラスを特定できない銘柄などは保留にする。JDK 17以上とアプリと同じ `org.json:json:20240303` のJARを使用する。

```sh
python tools/us_monitor_ledger.py 2026-11-17 \
  --close-cache /path/to/us-daily-closes.json \
  --companyfacts /path/to/companyfacts.zip \
  --json-jar /path/to/json-20240303.jar \
  --output /path/to/us-monitor-universe.json
```

為替と分割の参考判定を出す場合は、同じ取引日の取得資料を `--fx-snapshot`（Frankfurter v2 USD/JPY）と `--split-snapshot`（DoltHubの分割照会結果）で渡す。分割照会は直前150暦日から取引日までの `split` 表を `act_symbol` で集約し、`symbol` と `CAST(MAX(ex_date) AS CHAR) AS split_date` を返す。集計と判定の内訳は標準出力に出る。生成する台帳に終値を含めない。

生成した日の照合件数をAndroidに表示する場合は、ローカルで `gradle -PusMonitorFile=/path/to/us-monitor-universe.json :app:assembleDebug` を実行する。別日の終値にはその台帳を適用しない。銘柄一覧との終値照合は台帳の組み込みなしでも日次で動く。

### Androidで米国株の財務を更新して無音通知する

アプリを起動し、無音通知を許可する。終値の取得後、Wi-Fiなど従量制でない回線につながると、AndroidがNYSE・Nasdaqの上場銘柄一覧をSEC発行体一覧に照合する。SECから財務元データを銘柄ごとに取得し、進捗と照合済みの件数を表示する。通信が途切れても、同じ終値データなら途中から再開する。取得した元データは処理後に破棄し、端末内には照合結果だけを保存する。次の取引日はSECの日次提出一覧を照合して、変更のない発行体の結果を再利用する。一覧が不足した場合や前回の全件取得から7日以上経った場合は、対象を再取得する。

財務・株数・為替・分割を確認できた銘柄を参考判定に使う。最初の判定は比較の基準として保存する。後の取引日に、新しく条件に入った銘柄や参考候補から優先候補へ変わった銘柄を無音で知らせる。Apple製コンピューターの設定、同期、USBデバッグ、APIキーの入力は不要。取得状況は通信速度とAndroidのバックグラウンド実行に依存する。

### 米国株の同日再試行を過去データで再生する

`tools/UsRetryReplay.java` はアプリの終値再取得、SEC財務、判定、通知候補抽出のロジックをJVM上で使う。入力をローカルの作業ディレクトリに置き、取引日の終値を1銘柄、SEC財務を別の1銘柄だけ初回から除外して、再取得前後の件数を比べる。当日上場一覧がないときは実際に使用した一覧の日付を出力する。

- `closes.json` は比較日と当日のDoltHub API応答。各行に `symbol`、`trading_date`、`close` を含める。
- `supplement.json` は当日の除外ティッカーを指定して再取得したDoltHub API応答。 `splits.json` は同じ対象の分割照会結果。
- `nyse.txt` と `nasdaq.txt` はNasdaq Traderの `otherlisted.txt` と `nasdaqlisted.txt`。 `sec.json` はSECの `company_tickers_exchange.json`。 `fx.json` は比較日・当日のUSD/JPY。
- 銘柄ごとのSEC Company Factsは `TICKER.json` とし、再取得対象のCompany Factsを `TICKER-retry.json` とする。入力・株価原本はGitに入れない。

JDK 17以上とJSONライブラリ（既存のJVMテストと同じ `org.json:json:20240303`）で、リポジトリの `android-private` 直下から実行する。

```bash
src=app/src/main/java/jp/valuehunter/privatewatch
javac --release 17 -cp "$US_REPLAY_JSON_JAR" -d "$US_REPLAY_CLASSES" \
  "$src"/{UsFinancialFacts,UsDeviceFinancials,UsReferenceAlerts,ValueCandidateScreen,UsDoltCloses,UsScreen,UsDailyValuation,UsMarketCoverage,JapanScreen,UsDailyCloses,UsMonthlyHistory,UsSingleSessionBudget,ValueAlertMeter}.java \
  tools/UsRetryReplay.java
java -cp "$US_REPLAY_CLASSES:$US_REPLAY_JSON_JAR" jp.valuehunter.privatewatch.UsRetryReplay \
  "$US_REPLAY_INPUT" 2026-11-16 2026-11-17 INTC CSCO
```

#### 上場照合で保留になった銘柄を再検証する

同じJDKとJSONライブラリで、上の `javac` の末尾に `tools/UsDatedRetryReplay.java` を追加する。
保存済みの11月17日分の監査を使う場合は、`android-private` 直下で次を実行する。

```bash
java -cp "$US_REPLAY_CLASSES:$US_REPLAY_JSON_JAR" jp.valuehunter.privatewatch.UsDatedRetryReplay \
  ../docs/us-dated-listing-audit-20261117.json
```

監査JSONだけで実行すると、保留・除外理由を再集計する。株価配信元に参考終値があった記録があっても、元の上場一覧を照合できるまでは補完に数えない。終値や正式判定の件数は監査対象銘柄の中での件数。

上場一覧と終値などの原本を確保できた場合は、第2引数にその原本を置いた非公開ディレクトリを渡す。日付別の上場一覧は `YYYY-MM-DD-nyse.txt` と `YYYY-MM-DD-nasdaq.txt` を比較日・当日分用意する。`closes.json` には補完前の比較日・当日の終値、`supplement.json` には補完時の当日終値を入れる。`sec.json`、`fx.json`、`splits.json` は上と同じ形式で、SEC財務は `CIK0000012345.json` のようにCIKを10桁で表したファイル名にする。照合に通った銘柄だけを計算し、結果JSONには件数・銘柄コード・保留理由を出す。通知候補の再処理も検証できる。通知の送信は行わない。

`--single-session` を監査JSONの前に付けると、比較日の上場資料・終値やSEC財務を使わず、当日の上場一覧、DoltHubの当日参考終値、当日為替で100株の円換算額を確認する。私用ディレクトリで必要なのは当日の両市場一覧、`supplement.json`、`fx.json`。Androidでは「当日の予算チェック」として集計し、割安判定数や通知候補には加えない。対象日の上場原本がなければ比較日だけを緩和しても保留になる。
